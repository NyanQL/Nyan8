# PRタイトル

v0.0.19: APIチェックの適用拡張とPush配信・実行時ヘルパーの挙動修正

# PR本文

## 概要

APIにチェックを設定していても、ルートHTTP・WebSocket・内部呼び出し・MCP・OAuthなどの経路では実行されない状態を修正します。対応経路で`paramCheck → 本体 → outCheck`を実行し、`checkOnly`では入力チェックだけで終了します。

同じAPIにA・B・CがWebSocket接続している場合は、3接続すべてへPushを配信します。1接続の終了で他の接続まで登録解除される問題と、通常応答・Pushの同時書き込みを修正し、呼び出し元のエラー結果ではPush先を実行しないようにします。

併せて、WebSocket・Push・HTTP MCPからのリクエスト情報取得、ファイル操作の基準ディレクトリ、JavaScriptヘルパーの失敗時の扱いを整理します。

## 主な変更

### チェックの適用経路

- `/?api=API名`、`nyanCallMe`、WebSocketの各メッセージ、Push先、MCP HTTP／stdio、OAuthへ前後チェックを適用します。
- WebSocketはAPI指定の接続前にも入力チェックを実行します。接続時の`checkOnly`はHTTPで結果を返し、WebSocketへ切り替えません。
- チェックは`success: true`かつ`status: 200`だけを通過とします。入力拒否・`checkOnly`では本体を実行せず、出力拒否では本体結果を送信しません。
- `nyanCallMe`の有効なチェック拒否は`{success, status, result}`を戻り値にします。チェック自体の実行・解析エラーはJavaScript例外として扱います。
- MCPは入力スキーマ検証後にチェックを実行します。拒否・`checkOnly`の結果は`content`と`structuredContent`に格納し、拒否時は`isError: true`とします。
- OAuthはHTTP用hookだけでなく、Go生成メタデータと内部の`verifyAccess`にもチェックを適用します。Toolの`checkOnly`でも認証は省略しません。
- チェック・本体・内部呼び出し・Pushで同じAPI設定スナップショットを引き継ぎます。schedule・ws_clientも、実行する定義とスナップショットの世代を合わせます。

### Pushとリクエスト情報

- APIごとに複数の接続を保持し、配信開始時の全購読接続へ同じ結果を送ります。Push先のチェック・本体は各1回だけ実行します。
- 切断・送信失敗した接続だけを除去し、送信失敗後も残りへの配信を続けます。接続ごとの書き込みを直列化します。
- `nyanCallMe`でも呼び出し先APIの`push`を実行します。Push先の前後チェックを行い、元のリクエスト情報と内部呼び出しの引数を引き継ぎます。
- 呼び出し元の`status`が200～399で、トップレベルの`success`が真偽値の`false`ではない場合だけPushを開始します。例外・チェック拒否・`checkOnly`でもPushしません。
- Cookie・IP・User-Agent・ヘッダー取得関数を、WebSocket接続後・Push先・HTTP MCPの前後チェックと本体から利用可能にします。`nyanCallMe`先にも引き継ぎます。
- WebSocketは接続時、Pushは呼び出し元、HTTP MCPは現在の`tools/call`の情報を参照します。これらの経路は読み取り専用で、`nyanSetCookie`は応答を変更しません。

### ファイル操作・ヘルパー・依存関係

- `nyanGetFile`・`nyanReadFileB64`・メール添付の相対パスを、最上位の`api.json`のディレクトリ基準へ統一します。多段include先でも共通です。
- `nyanCallMe`の暗黙の`hello2`呼び出しを廃止し、非空の文字列の`api`を必須にします。
- `nyanHostExec`はコマンドの非0終了も、終了コード・標準出力・標準エラーを含む失敗結果として返します。シェル起動失敗などは例外を維持します。
- `nyanSetCookie`はNyan8がTLSで受信した場合に`Secure`を付けます。
- OAuth用`nyanRandomBase64URL`は引数省略時32バイト、指定範囲1～1024バイトとします。
- `BinaryVersion`を`v0.0.19`へ更新します。`golang.org/x/crypto`を`v0.52.0`、`x/net`を`v0.55.0`、`x/text`を`v0.37.0`、`x/sys`を`v0.45.0`へ更新します。
- READMEに経路ごとの仕様、OAuth hookの入出力、共有サーバーメモリの性質を記載します。実装は`main.go`、テストは`main_test.go`に集約し、その方針と18項目の検討結果を記録します。

## 互換性・移行時の注意

- **これまでチェックされなかった経路でも拒否されるようになります。** WebSocket接続時に必要な入力は接続リクエストへ渡してください。接続時のクエリ値は、各メッセージへ自動継承されません。
- **`nyanCallMe()`や`nyanCallMe({})`は使えません。** 呼び出し先を明示してください。未指定の例外を捕捉しなければ通常HTTPでは500になります。チェック拒否については戻り値の`success`・`status`を確認してください。
- **実行時の相対ファイルパスの基準が変わります。** バイナリの配置先や起動時の作業ディレクトリを前提にしている場合は、最上位の`api.json`基準へ修正するか絶対パスを指定してください。設定JSON内の`script`・include先などの相対パス規則は変更しません。
- **内部呼び出し先の`push`も動作するようになります。** 子APIのPushは`nyanCallMe`が戻る前に実行し、親APIのPushとは別です。後から親が拒否・エラーになっても、子の配信は取り消しません。Push先の拒否・実行エラーは子APIの戻り値を置き換えません。
- **`nyanHostExec`の非0終了を`catch`だけで処理しないでください。** 戻り値の`success`／`exit_code`を確認する必要があります。
- MCPの`checkOnly`でも入力スキーマ検証を行います。`additionalProperties: false`などを使う場合は、必要に応じて`nyan_mode`をスキーマで許可してください。
- OAuthの出力拒否では、本体のCookieやリダイレクト先も送信しません。本体で実行済みのstate保存などの副作用は取り消しません。
- Pushは全購読接続へ同じ内容を配信します。受信者別の認可判定や内容の作り分けは行いません。取得するCookieなども受信者ではなく呼び出し元の情報です。
- `Secure`判定はNyan8へのTLS接続に基づきます。HTTPS終端プロキシからHTTPで転送する構成では、転送ヘッダーだけで`Secure`は付きません。

## 残る仕様・制約

- MCPはToolの参照先APIの`push`を自動実行しません。ただし、Tool内の`nyanCallMe`による呼び出し先のPushは実行します。schedule・ws_client定義自体への前後チェック追加は対象外です。
- JSON-RPCで本体が`success: false`を返した場合は、従来どおりエラー応答で終了し、`outCheck`へ進みません。
- Pushには切断中の結果を保存・再送する機能はありません。
- `nyanGetItem`は共有サーバーメモリを使用し、未登録キーは現在も空文字列です。未登録時の戻り値の統一方針は今回確定していません。
